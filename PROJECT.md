# mercy-platform — CURRENT

## Назначение и границы
«Язык милосердия» — русскоязычная платформа добровольной помощи и координации поддержки людям в сложной жизненной ситуации. MVP включает публичные просьбы о помощи с приватными контактами и действиями владельца, приватное предложение добровольной помощи, staff workspace и каталог проверенных организаций. Помощник не становится сотрудником и не получает доступ к обращениям автоматически.

Mercy не является медицинской организацией или 24/7 экстренной службой. Медицинские услуги, профессиональные медицинские исполнители, qualification/licence verification, booking, payments, commissions, ratings и medical marketplace не входят в Mercy и не должны возвращаться в его модель данных или UI.

## Инфраструктура
Mercy связан с каноническим Peerivo Global Contract через `.peerivo/global-contract.json`. Этот binding — единственный источник точной authority/version/digest/Git SHA для проекта; перед effectful work действует иерархия `Global -> Project -> Agent -> Task/Run`, а локальные правила могут только усиливать ограничения.

Модульный монолит Next.js 16 / React 19, Supabase Auth/PostgreSQL/PostGIS/Realtime, append-only SQL migrations и non-root Docker runtime. Production data/auth перенесены на российский self-hosted Supabase в Beget; канонический публичный API — `https://api.mercy.peerivo.net`. Приложение также переведено на REG.RU: successful PREPARE `36044040364` и public VERIFY `36044738898` подтвердили live revision на `https://mercy.peerivo.net`; Vercel остаётся preview/rollback-контуром. Старый managed Supabase source остаётся write-frozen как rollback-контур. Все remote migrations применяются только через защищённый GitHub Actions workflow; секретов в репозитории нет.

## IMPLEMENTED
- Repository application runtime intentionally has no checked-in `compose.yaml`/`docker-compose*.yml`: CI, Vercel and REG.RU build from the pinned `Dockerfile`, while remote self-hosted Supabase Compose is discovered on Beget through Docker labels. This keeps dependency inventory provable to Global Threat Radar instead of introducing an opaque repository manifest.
- Production job `Repair Beget Auth URLs` остаётся только `workflow_dispatch` + exact current `main` + `REPAIR_AUTH_URLS` и единственный имеет `environment: production`. Сам workflow дополнительно разрешает изолированный push-test только на `test/auth-repair-workflow-*`: без production Environment/secrets он syntax-check’ит repair scripts, запускает focused tests, собирает production Next.js и проверяет callback verifier против локального internal origin до любого production run.
- Remote Auth repair выполняется через streamed `bash -s`; Docker Compose команды без собственного stdin обязаны явно читать из `/dev/null`, чтобы disposable preflight или recreate не могли поглотить оставшуюся часть скрипта. Public callback verification проходит ограниченную цепочку только same-origin 307/308 redirects и принимает конечный `/auth`/`/auth/` только при query-параметре `error=callback`; внешний origin и циклы fail closed.
- Auth: регистрация с подтверждением email, вход/выход, recovery и проверяемый callback на обязательный `NEXT_PUBLIC_SITE_URL`; callback redirects всегда строятся от canonical `siteUrl()` и никогда не доверяют `Request.url`/reverse-proxy origin, чтобы внутренний `0.0.0.0:3000` не мог попасть в публичный redirect. В общей шапке используется один auth-пункт `Вход`, который при активной сессии становится `Кабинет`. Обычный `Выйти из аккаунта` находится внутри кабинета, а `Быстрый выход` показывается только при приватном доступе к карточке обращения/чату, не в общей шапке.
- «Нужна помощь»: публичная карточка и список просьб без приватных контактов; личный кабинет владельца, ADMIN queue, назначение/переназначение, COORDINATOR workspace, приватный Realtime-чат, план и переходы до RESOLVED/CLOSED. Доступ к приватной части определяется user JWT, RLS и активным назначением.
- «Хочу помочь»: категоризированное предложение с страной/городом или online, описанием, контактом и атомарно сохранённым consent; собственный список в кабинете; ограниченная ADMIN-модерация с audit. Предложение не меняет staff role.
- Публичные просьбы: фильтры, безопасный share, жалобы и ADMIN-модерация жалоб.
- Quick Exit/History/BFCache guards, приватные no-store/noindex routes, каталог проверенных организаций, CI с clean disposable Supabase/pgTAP/integration/Chromium и Docker.
- Общий адаптивный `page-shell`, единые формы/карточки/навигация и favicon/знак Peerivo.
- SEO/discovery baseline: production `NEXT_PUBLIC_SITE_URL` нормализуется через единый helper; `/robots.txt` не скрывает страницы, которым нужно наблюдаемое `noindex`; sitemap содержит только публичные indexable surfaces; `/auth`, `/feedback`, `/help`, consent/private utility surfaces остаются `noindex`; canonical URL списка просьб сохраняет номер страницы и отбрасывает фильтры; опубликован IndexNow ownership key.
- `/health` выдаёт только status, environment и безопасно нормализованную ревизию; `/health/data` выполняет bounded public RPC readiness probe с 5-секундным abort и никогда не возвращает строки/конфигурацию. Docker принимает `GIT_SHA` и обязательные публичные Auth/Supabase build variables. Mock/data fallback отсутствует.
- Security dependency baseline: Playwright `1.55.1`, Vitest `4.1.0`, nested Supabase CLI `tar` принудительно фиксируется на `7.5.22`; все стадии Dockerfile используют один immutable `node:22-alpine` digest, все внешние GitHub Actions во всех workflows закреплены 40-символьными commit SHA, а package binaries запускаются из lockfile-installed `node_modules` без `npx/npm exec`. Regression test запрещает возврат mutable executable dependencies. Machine-managed threat locks снимаются только authoritative full Threat Radar rescan после merge.
- Migration preflight для перехода Mercy на Beget запускается вручную через GitHub Actions и fail-closed проверяет production configuration (host/user могут храниться как Environment Variables, чувствительные значения — только Secrets), pinned SSH host key, source/target DB versions, пустой target Mercy contour и доступность требуемых Postgres extensions. Расширение PostGIS может быть ещё не установлено в свежей Beget-БД: preflight требует, чтобы оно было доступно в `pg_available_extensions`, а начальная Mercy migration устанавливает его. Source DB password не передаётся в process argv; preflight не выгружает пользовательские данные и не изменяет Beget.
- Cutover workflow `Cut over Mercy Supabase to Beget` требует явный выбор `MIGRATE`, повторяет compatibility gates, запрещает Storage/MFA/SSO/non-email migration profile, делает backup цели, freeze source атомарной транзакцией с Docker stdin `-i` и проверкой покрытия по конкретным relations, применяет schema + Auth/public data + migration history одной target-транзакцией через remote shell, изолированный от локальной подстановки переменных, нормализует исторический specialist Storage bucket к подтверждённому пустому source-профилю внутри bootstrap-транзакции с временным `session_replication_role=replica` только на удаление известного пустого bucket и автоматически unfreeze-ит source при failure и оставляет source frozen только после полной target verification. После post-apply failure target автоматически восстанавливается из safety backup полным пересозданием target database с последующим `pg_restore`, сохранением database-level settings/ACL, object ownership/ACL и проверкой service-role доступа. Явный `recover_from_run_id` допускается только после независимой проверки GitHub Actions, что указанный main-branch cutover завершился `failure`, `timed_out` или `cancelled`, и блокируется после любого подтверждённого успешного cutover. Для новых backup destructive restore разрешён только при наличии `prepared` marker и database metadata fingerprint; историческое legacy-исключение для run `35770879007` использовано при успешном recovery и теперь постоянно закрыто для повторного restore. Перезапуск Supabase сервисов выполняется по Docker Compose labels без доступа deploy-user к каталогу `/opt/beget/supabase`.

- REG.RU application cutover/deploy управляется protected workflow `Deploy REG.RU production`: `PREPARE` требует exact current `main` SHA, проверяет публичный Beget key до SSH, ставит immutable candidate на `127.0.0.1:3100`, arm-ит rollback до удаления старого контейнера и до promotion проверяет local `/health`, bounded `/health/data`, 308 русского hostname и Auth callback `307/308 -> https://mercy.peerivo.net/auth?error=callback`; любой такой failure откатывает candidate. DNS не меняется. `VERIFY` остаётся public-read-only exact-SHA проверкой. `язык-милосердия.рф`/`www` перенаправляются 308 на `https://mercy.peerivo.net` с сохранением path/query.
