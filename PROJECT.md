# mercy-platform — CURRENT

## Назначение и границы
«Язык милосердия» — русскоязычная платформа добровольной поддержки материнства, семьи и людей в кризисе: приватное обращение, назначенный координатор, чат, совместный план и проверенный каталог. Это не медицинская организация и не 24/7 экстренная служба. Помощь не зависит от решения человека или участия в религиозной поддержке; опасные отношения не предлагается сохранять.

## Инфраструктура
Модульный монолит Next.js 16 / React 19, Supabase Auth/PostgreSQL/PostGIS/Realtime, SQL-only migrations, Docker. Production Supabase внешний; секретов в репозитории нет. Remote migrations intentionally not applied.

## IMPLEMENTED
Публичная главная, каталог/гео-RPC, Auth flows, приватная форма обращения, кабинет, история/Realtime чат с RPC-idempotency, просмотр плана, предложение помощи, быстрый выход с ранним initial/History/BFCache/client-navigation guard и явным возвратом; строгая схема, RLS/grants, assignment/status/staff-role RPC, audit, consent and IdentityLink contract; CI, controlled migration deployment, docs and Docker. Mercy также хранит профессиональные анкеты специалистов: собственник создаёт/редактирует и отправляет анкету, ADMIN журналируемо публикует, отклоняет или блокирует и отдельно решает статус квалификации. ADMIN может заблокировать опубликованный профиль либо отозвать его подтверждение с автоматическим снятием публикации и возвратом на проверку; владелец не может снять блокировку. Опубликованная проекция поддерживает безопасный фильтрованный поиск, стабильную пагинацию и карточку. Квалификационные файлы зарезервированы в приватном bucket, а медицинское подтверждение и публикация с VERIFIED закрыты, пока каждая нормализованная медицинская категория не покрыта активным правилом той же нормализованной страны. Отключение правила не мешает ADMIN заблокировать уже опубликованный VERIFIED-профиль или отозвать подтверждение. Версионированный будущий Hiring Network transfer contract описан без сетевой интеграции.

Минимальное рабочее место сотрудников добавляет ADMIN-очередь с ограниченной маршрутизационной проекцией, выбор действующего координатора, назначение/переназначение с обязательным основанием и пагинацию. Координатор видит только активные назначения, открывает существующую приватную карточку и чат и меняет статус через существующий атомарный RPC; ADMIN не получает содержание обращений только благодаря роли.

## IN_PROGRESS
Полный CI corrective-ветки каталога специалистов ещё требуется. Публичная проекция больше не допускает неограниченное перечисление через PostgREST: каталог использует ограниченный поиск, а карточка — lookup одного опубликованного UUID. Первичное решение принимается только по отправленной анкете; исключения для опубликованного профиля ограничены блокировкой и отзывом подтверждения. Предыдущая проблема PR #13 с ожиданием регистрации уже находится в основной истории.

Операционная проверка рабочего места на staging остаётся необходимой до работы с реальными обращениями; карта и новые продуктовые возможности не входят в эту итерацию. Текущий head должен быть фактически подтверждён обязательным GitHub CI: clean Supabase, 34 pgTAP, 10 Auth/API/Realtime, полный production Chromium и Docker build. Безопасность возврата приватного чата проверяется независимо от того, восстановил Chromium документ или загрузил его заново; отдельный cacheable test fixture импортирует production guard и требует настоящее `pageshow.persisted=true`, не утверждая при этом BFCache-совместимость приватного `no-store` чата.
