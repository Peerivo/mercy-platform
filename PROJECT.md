# mercy-platform — CURRENT

## Назначение и границы
«Язык милосердия» — русскоязычная платформа добровольной поддержки материнства, семьи и людей в кризисе: приватное обращение, назначенный координатор, чат, совместный план и проверенный каталог. Это не медицинская организация и не 24/7 экстренная служба. Помощь не зависит от решения человека или участия в религиозной поддержке; опасные отношения не предлагается сохранять.

## Инфраструктура
Модульный монолит Next.js 16 / React 19, Supabase Auth/PostgreSQL/PostGIS/Realtime, SQL-only migrations, Docker. Production Supabase внешний; секретов в репозитории нет. Remote migrations intentionally not applied.

## IMPLEMENTED
Публичная главная, каталог/гео-RPC, Auth flows, приватная форма обращения, кабинет, история/Realtime чат с RPC-idempotency, просмотр плана, предложение помощи, быстрый выход с ранним initial/History/BFCache/client-navigation guard и явным возвратом; строгая схема, RLS/grants, assignment/status/staff-role RPC, audit, consent and IdentityLink contract; CI, controlled migration deployment, docs and Docker. `send_message` повторно проверяет доступ при retry, обнаруживает nonce-конфликт и атомарно сериализует минутную квоту по автору. Приватные RPC имеют явные EXECUTE grants, а новые функции по умолчанию не открываются API-ролям. Disposable Supabase harness воспроизводит схему и запускает pgTAP, настоящие Auth/API/Realtime (включая независимые сценарии переназначения и отзыва staff-role на открытом соединении) и Chromium-сценарии без облачных credentials; обычный Back после Quick Exit и настоящее BFCache-восстановление разнесены по независимым сценариям. Realtime-чат закрывает канал и WebSocket на `pagehide`, а при `pageshow.persisted` повторно проверяет сессию, подписывается и догружает историю. BFCache-сценарий хранит обезличенные `pageshow`/`pagehide` наблюдения вне page storage, привязывает обе формы CDP-причин к целевому Back-переходу и публикует безопасный JSON artifact даже при падении. Integration Auth-клиенты изолированы, явно передают пользовательский JWT в Realtime и работают в Node environment; готовность PostgreSQL-подписки требует и `SUBSCRIBED`, и `system postgres_changes/ok`, запрещённая доставка проверяется двухсекундным окном, а retry прежнего nonce после потери назначения явно запрещён. Пользовательский чат не пересоздаёт канал при изменении сообщений и после фактической PostgreSQL-готовности постранично догружает всю историю по устойчивому курсору `(created_at, id)`; отдельный Realtime-поток дедуплицируется по UUID и не передвигает курсор завершённой истории.

## IN_PROGRESS
В PR #13 прогон 34777308512 подтвердил настоящий BFCache guard и callback, но сценарий двух пользователей остановился на входе после регистрации. Устранена гонка подготовки: тест ожидает успешный `/auth?check=email` до перехода к входу. Полный CI нового head ещё требуется.

Полный браузерный UI рабочего места администратора/координатора остаётся отдельным следующим этапом; карта и новые продуктовые возможности также не входят в это объединение. Текущий head должен быть фактически подтверждён обязательным GitHub CI: clean Supabase, 20 pgTAP, 9 Auth/API/Realtime, полный production Chromium и Docker build. Безопасность возврата приватного чата проверяется независимо от того, восстановил Chromium документ или загрузил его заново; отдельный cacheable test fixture импортирует production guard и требует настоящее `pageshow.persisted=true`, не утверждая при этом BFCache-совместимость приватного `no-store` чата.
